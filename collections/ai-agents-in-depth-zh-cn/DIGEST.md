## 这本书在讲什么

这本书试图回答的不是“怎样写一个更聪明的提示词”，而是怎样把模型能力转化为能在真实环境中持续完成任务的系统。作者用一句公式统一全书：`Agent = LLM + 上下文 + 工具`。LLM 是决策策略，上下文决定模型此刻能观察到什么，工具决定它能对外部世界做什么。三者通过“思考、行动、观察”的循环形成轨迹，但只有模型说“完成了”并不代表环境真的改变，真正的完成必须由外部状态验证。

这个统一模型带来一个重要转向：失败不再自动等价于“模型不够强”。模型可能没看到必要信息，工具可能没有表达正确动作，运行时可能丢了状态，验证器可能奖励了错误路径，权限边界也可能允许不可逆副作用。围绕模型构建的上下文管理、工具契约、验证、恢复、评估与治理层，被作者统称为 Harness。它不是 API 薄封装，而是把概率性模型变成生产系统的关键工程载体。

全书的论证链由此展开：先确定 Agent 的观察、动作和自治边界；再建设上下文、知识、工具、代码与故障闭环；随后用可复现评估区分“偶尔能做成”和“持续可靠地做成”；最后把真实轨迹中的经验路由到知识、指令、程序或参数，并用独立验证、灰度和回滚形成持续进化。语音、GUI、机器人和多 Agent 不是另一套理论，只是把同样的观察、动作、反馈和验证原则扩展到更快、更动态或更多主体的环境。

## 一、先画清 Agent 的边界

### 1. 用观察、策略、动作、反馈诊断系统

**它解决什么问题**：Agent 失败时，团队很容易直接换模型或加提示词，却没有定位首个断点究竟在哪里。

**核心逻辑**：先冻结可重放任务，把链路拆成四面：必要信息是否进入上下文，模型是否作出正确决策，工具是否允许并正确执行动作，结果是否回到下一轮并被验证。每次只改变一面，比较同一轨迹前缀上的差异。书中的上下文消融显示，缺工具定义时模型无法行动，缺工具结果时会重复调用，缺历史时会重做已完成步骤；这些都不是同一种“智力不足”。XLeRobot 的分阶段实验同样先用真人闭环排除硬件动作空间问题，再把差距收窄到策略、反馈与仿真迁移。

**什么时候会失效**：事故仍在扩大时先止损，不要为了完整归因延误熔断；没有轨迹、环境和版本证据时，也不能用四面框架包装猜测。

→ 深入：[`diagnose-agent-boundaries`](../../skills/ai-agent/foundations/diagnose-agent-boundaries/SKILL.md)

### 2. 自治不是开关，而是按局部分配

**它解决什么问题**：团队常在固定工作流和“全自动 Agent”之间二选一，把自治程度当成产品标签。

**核心逻辑**：先看路径是否会被中间观察改变，再看结果能否自动验证，最后看错误动作的副作用。路径固定、验收确定的部分应留在程序；需要根据新证据选择下一步、且有恢复和验证的局部才交给 Agent；高风险动作必须收窄权限、增加审核或人工接管。司法问答对照说明，单一法条查询用一次检索更快且质量相近，复杂量刑问题的证据路径依赖中间结果，才值得付出 Agentic RAG 的额外延迟。

**什么时候会失效**：不要因为流程里存在一个分支就把整条链 Agent 化，也不要用“更灵活”掩盖无法自动验收的高风险动作。

→ 深入：[`choose-agent-autonomy`](../../skills/ai-agent/foundations/choose-agent-autonomy/SKILL.md)

### 3. 上下文工程先处理布局，再处理容量

上下文不是越多越好。它既是模型的观察空间，也是一种昂贵且会衰减的工作记忆。书中将其治理拆成四个互补方法。

#### 稳定前缀与动态后缀

系统提示、静态参考和核心工具定义应以确定性顺序组成字节稳定的前缀；时间、状态、新观察和按需工具定义只追加到后部。实验显示，只是在系统提示前部加入动态时间戳，或每轮重排语义相同的工具 schema，都可能让后续缓存整体失效。对 120 多个工具的场景，更合理的做法是常驻小型能力目录和发现入口，命中后再把详细 schema 追加到轨迹。

这一方法只在服务端支持缓存、调用有可复用前缀且收益可测时成立。低流量短请求不值得为缓存重构可读性良好的上下文。

→ 深入：[`design-cache-stable-context`](../../skills/ai-agent/context-knowledge/design-cache-stable-context/SKILL.md)

#### 能力按缺口渐进披露

启动时只暴露 Skill 名称、触发条件和少量核心工具；真正命中任务后加载主流程，细则、脚本和参考资料再按执行缺口读取。PPTX 案例中，Agent 不需要开局吞下所有 XML 规范，只需先识别“从论文生成演示稿”，随后按步骤加载 `html2pptx`、布局参考和验证脚本。这个设计同时降低 token、缓存扰动和工具误选。

边界在于：不可逆动作所需的安全规则不能延迟到执行后才加载；目录本身也必须足以区分相邻能力，否则“按需”会变成漏加载。

→ 深入：[`progressively-disclose-capabilities`](../../skills/ai-agent/context-knowledge/progressively-disclose-capabilities/SKILL.md)

#### 把隐式状态变成确定性投影

长轨迹里的时间、工具次数、TODO、等待任务和当前阶段，不应让模型每轮重新从历史统计。运行时应从事件日志确定性归约一个短状态栏，并保留来源与恢复指针。书中的状态栏实验使弱模型准确率提高 40 至 54 个百分点，也让强模型的思考量、延迟和成本大幅下降；异步场景则用明确的 `pending` 状态避免模型把占位符误当真实结果。

状态栏是有损投影，不是真源。若允许模型自由改写，或状态字段没有事件依据，它会以更高权威传播错误。

→ 深入：[`distill-explicit-agent-state`](../../skills/ai-agent/context-knowledge/distill-explicit-agent-state/SKILL.md)

#### 隔离优先，压缩兜底

高噪声、低共享的子任务应放进独立上下文，只向主任务返回结构化结论、证据和未决项；无法隔离的内容再做任务感知压缩。六种压缩策略的对比表明，逐项摘要会碎片化，简单拼接会截掉后部证据，无压缩又会在长轮次溢出。十网站搜索案例更直接：各浏览 Agent 保留自己的网页轨迹，Manager 只接收状态和证据化结果，命中后级联取消其余任务。

隔离不是“少回传日志”。在创建子 Agent 前，必须先写清自包含输入、输出、权限、预算和验收；若子任务频繁依赖快速变化的共享隐式状态，隔离成本可能高于噪声收益。

→ 深入：[`isolate-before-compressing-context`](../../skills/ai-agent/context-knowledge/isolate-before-compressing-context/SKILL.md)

### 4. 记忆和检索必须保留证据真源

#### 长期记忆采用“追加证据，重建视图”

用户记忆和经验知识不应靠覆盖式摘要维护。原始对话、环境结果、时间、主体与来源作为追加证据；概览、冲突合并、索引和检查点只是可重建派生视图。作者的双层用户记忆用结构化卡片常驻关键概览，再按需回查原对话，因而能区分多辆车、识别电汇指令先后，并把护照到期日与机票关联。GAIA 经验提炼则同时看成功、失败和部分成功轨迹，只有跨轨迹支持并在留出任务正向迁移的原则才进入正式知识。

一次成功、模型自己的反思或来源不明的摘要都不能直接成为长期事实；敏感信息还需要目的、期限和删除机制。

→ 深入：[`build-evidence-backed-memory`](../../skills/ai-agent/context-knowledge/build-evidence-backed-memory/SKILL.md)

#### RAG 模式由问题几何决定

先定义答案需要的证据集合，再选最小控制流：单一事实用固定检索；精确编号与语义表达并存时用稀疏、稠密召回和小候选重排；证据路径依赖中间结果时才用 Agentic RAG；全库统计则必须结构化聚合或全量扫描，不能从 Top-k 外推全集。司法问答说明简单查询无需多轮，复杂量刑才从迭代证据缺口中受益；混合检索实验则展示关键词和向量各自覆盖不同盲区。

不要看到问题很长就自动多跳，也不要给 300 行结构化订单表加向量库。任何新增检索阶段都应对应一个已观察到的盲区，并有来源、覆盖和停止条件。

→ 深入：[`choose-rag-retrieval-mode`](../../skills/ai-agent/context-knowledge/choose-rag-retrieval-mode/SKILL.md)

## 二、用 Harness 把“能做”变成“做对”

### 5. 工具契约同时定义能力和信任边界

**它解决什么问题**：函数签名看似清楚，并不等于模型理解副作用、权限、幂等性和成功条件。

**核心逻辑**：工具要暴露结构化输入输出、前置条件、失败分类和可观察后置状态；权限按动作风险最小化，危险操作在执行前门控，执行后再从服务端真值验证。书中的执行工具 MCP 为文件、终端、解释器、数据和 GUI 分别配置超时、沙箱与审查；动态应用把租户隔离、状态机和引用完整性下沉到稳定数据层，使生成代码无法绕过。提示注入防御也不能只靠自然语言警告，而要把外部内容标成数据，并在执行侧阻止越权动作和记忆污染。

**什么时候会失效**：把所有操作塞进一个万能工具会抹掉权限和验证语义；让模型自报“执行成功”也不能替代环境真值。

→ 深入：[`design-trusted-agent-tools`](../../skills/ai-agent/tools-runtime/design-trusted-agent-tools/SKILL.md)

### 6. 审核必须带来异源证据

**它解决什么问题**：同一模型“再检查一次”经常重复同一盲点，看似多了一层审核，实质没有新信息。

**核心逻辑**：提议者与审核者要在证据、上下文或权限上独立。Claude Code Sidecar 只看工具名、参数和权限元数据，在副作用发生前并行门控；PPT Reviewer 不复述 Slidev 源码，而是检查真实渲染截图中的溢出、字号和图表一致性；自修改 Agent 只能提交候选，稳定版本、测试和批准权由外部流程掌握。审核输出必须指向证据、失败条件和可执行退回项。

**什么时候会失效**：确定性验证器已经足够时不要再加模型审核；审核者与提议者共享同一输入、锚点和权限时，多一个角色名并不会增加可信度。

→ 深入：[`build-independent-review-loops`](../../skills/ai-agent/tools-runtime/build-independent-review-loops/SKILL.md)

### 7. 失败处理要成为有界状态机

**它解决什么问题**：Agent 遇到错误后要么无限重试，要么一次失败就退出；并发任务又常在已有结果后继续消耗资源。

**核心逻辑**：为每类失败定义检测信号、是否可重试、重试预算、幂等键、恢复动作、升级出口和终止确认。异步邮件案例用任务 ID、事件队列、`pending`、进度、取消和真实完成事件管理部分完成；参数或权限类确定性错误禁止原样重试；并行搜索把“已有一个经验证的成功”也视为终止事件，原子结算后向其余任务传播取消。

**什么时候会失效**：统一指数退避无法区分暂时故障和永久错误；没有服务端幂等与真实状态查询时，重试本身可能制造重复扣款等更大事故。

→ 深入：[`engineer-agent-failure-closure`](../../skills/ai-agent/tools-runtime/engineer-agent-failure-closure/SKILL.md)

### 8. 让语言负责表示，让程序负责求值

**它解决什么问题**：自然语言擅长解释意图和例外，却不擅长稳定执行精确计算、组合约束和重复流程。

**核心逻辑**：模型先把语义转成代码、约束、参数清单或工作流；确定性执行器计算；外部状态验证结果；失败时把反馈交回模型修正表示。骑士与无赖谜题用约束求解后准确率超过 90%，明显优于纯思考；航空政策把模型填写的条件交给服务器真实逻辑裁决；PreAct 则把一次成功浏览轨迹编译成带执行前后检查的程序，重复任务加速 8.5 至 13 倍，检查失效时退回完整 Agent。

**什么时候会失效**：形式化表示不完整时，程序只会稳定地产生错误；生成代码必须运行在受限环境，且不能修改自己的测试和验证器。

→ 深入：[`formalize-and-verify-agent-work`](../../skills/ai-agent/tools-runtime/formalize-and-verify-agent-work/SKILL.md)

## 三、没有评估，就没有可证明的进步

### 9. 分开能力上限与连续可靠性

**它解决什么问题**：团队常用最好一次演示证明生产成熟，也会用单次平均分掩盖连续失败风险。

**核心逻辑**：`Pass@k` 衡量给定多次探索预算后至少一次成功的能力上限，`Pass^k` 衡量连续 k 次都成功且不触发安全否决的可靠性。若单次成功率是 60%，五次里至少一次成功约为 99%，连续五次全对却只有约 7.8%。科研发现、漏洞挖掘和开放创作可关注前者；支付、退款、权限变更和生产部署更关心后者。书中四次自主科研只有一次走完整流程，恰好说明一次成功只能证明可能性。

**什么时候会失效**：独立同分布假设不成立时不能只套公式；必须说明 k 的采样方式、重试成本、选择器和一票否决项。

→ 深入：[`measure-capability-vs-reliability`](../../skills/ai-agent/evaluation/measure-capability-vs-reliability/SKILL.md)

### 10. 评估对象是模型与 Harness 的组合

**它解决什么问题**：静态问答准确率无法验证 Agent 是否真的改变环境、是否遵守过程约束，也无法复现工具和用户交互。

**核心逻辑**：先写可观察成功标准，再建设可重置环境、版本化任务集、用户模拟和工具协议，最后组合结果、过程与质量三层判断。退款客服 Rubric 分别核对订单、政策、到账与工具证据，并把幻觉设为否决；`τ²-bench` 同时控制用户逐步披露的信息和数据库最终状态；三层验证器只有在结果和过程硬门通过后才讨论语言质量。每次运行还要保存环境快照、轨迹、版本和统计区间。

**什么时候会失效**：LLM Judge 与被测模型可能共享偏差，仿真环境也可能与生产脱节；高风险结论仍需要隐藏真值、确定性检查或人工抽检。

→ 深入：[`build-reproducible-agent-evals`](../../skills/ai-agent/evaluation/build-reproducible-agent-evals/SKILL.md)

### 11. 从首个因果错误开始修

**它解决什么问题**：长轨迹最后一个报错往往只是后果，若直接修末端症状，系统会换一种方式失败。

**核心逻辑**：冻结输入、模型、工具、环境和完整轨迹，定位第一次不可接受的状态转换；区分主因、次因和连锁后果；提出最小因果假设，并在同一前缀上做单变量配对实验。生产日志解析案例从第一条未识别格式开始，而不是最后的工具链异常；AndroidWorld 每轮只替换提示、工具协议或模型变量；只有模型动作确实是首错时，才把该前缀构造成训练数据。

**什么时候会失效**：仍在发生的事故先做恢复闭环；不能稳定重放、同时修改多个变量或只凭模型自省时，归因结论不能进入正式修复。

→ 深入：[`attribute-first-errors`](../../skills/ai-agent/evaluation/attribute-first-errors/SKILL.md)

## 四、把经验写进正确的载体

### 12. 知识、指令、程序、参数各有自然边界

**它解决什么问题**：每个 bad case 都加 Prompt 会形成规则泥球，每个新事实都微调又无法追溯和撤销。

**核心逻辑**：先把经验原子化为触发条件、期望行为、例外、来源和可观察结果，再判断自然表示：带来源且会变化的事实进入知识；可清楚表达的操作原则进入指令或 Skill；必须一致执行的计算、权限和状态机进入程序；外部载体难以表达的统计能力才进入参数。法律案例原文保留为证据，聚类和摘要只是派生视图；航空政策用 Prompt 说明流程、服务端程序裁决真值；音色和副语言控制这类分布式表达习惯才适合参数学习。

**什么时候会失效**：一条更新混合事实、流程和约束时先拆分；需要精确撤销和来源追踪的内容不要藏进权重。

→ 深入：[`route-agent-updates`](../../skills/ai-agent/training-evolution/route-agent-updates/SKILL.md)

### 13. 先排除外部修复，再选 SFT 或 RL

**它解决什么问题**：模型表现不好时，训练经常成为昂贵的第一反应，而真实缺口可能只是上下文、工具或验证器错误。

**核心逻辑**：固定一个可复现失败，依次消融上下文、工具结果、权限、动作空间、局部规则和确定性程序。外部修复达标就停止。剩余的格式、术语和基础协议可用 SFT 固形；需要探索、延迟反馈和组合泛化的策略，在动作可解析、环境可靠和奖励可信之后再用 RL。航空客服实验中，规则组织被打乱使成功率下降超过 30%，证明上下文表达本身就可能是瓶颈；GeneralPoints 则显示小模型格式不稳时直接 RL 会失败，先稳定形式再塑造策略更可靠。

**什么时候会失效**：每周变化的价格和政策属于知识更新，不属于每周 SFT；没有可验证环境时不能把 RL 当成“更高级的微调”。

→ 深入：[`choose-sft-or-rl`](../../skills/ai-agent/training-evolution/choose-sft-or-rl/SKILL.md)

### 14. 奖励必须来自策略不能伪造的结果

**它解决什么问题**：Agent 会优化评分漏洞，而不是优化用户真正想要的状态。

**核心逻辑**：先把最终状态、允许路径和禁止路径写清，优先使用隐藏测试、数据库状态、服务器规则、权限日志等外部结果。若终局信号过稀，再只加入环境可观察、与进展单调相关且可消融验证的过程信号；每个分量记录产生者、时点、可见信息和允许路径。代码测试和航空政策服务器能提供比模型自评更可靠的基线；路径奖励在部分任务降低违规并加速探索，但当软件进展信号不可达时没有收益。

**什么时候会失效**：策略能读答案、改测试或用口头声明触发成功时，应立即隔离验证面；不可验证的“努力程度”和模型自评分不能成为可优化奖励。

→ 深入：[`design-verifiable-agent-rewards`](../../skills/ai-agent/training-evolution/design-verifiable-agent-rewards/SKILL.md)

### 15. 持续进化必须把在线执行与离线变更分开

**它解决什么问题**：未经筛选的在线自我修改会把偶然成功、攻击输入和评测偏差放大成长期行为。

**核心逻辑**：生产运行只追加带来源的候选证据，不直接改稳定策略；离线流程做归因、选择载体、生成最小 diff，并经过独立测试、canary、监控和回滚。稳定版本、验证器和发布权构成候选无法改写的可信根。Hermes 案例让 Agent 只提交更新提案，由外部 Reviewer 决定是否接纳；连续进化实验同时检查记住新经验、迁移到新任务、冲突时更新旧规则和保留仍有效能力，缺一项都不能称为进化。

**什么时候会失效**：候选被流程接受不等于能力已提升；没有旧任务保留集、冲突测试和回滚包时，不应开放持续更新。

→ 深入：[`govern-continuous-agent-evolution`](../../skills/ai-agent/training-evolution/govern-continuous-agent-evolution/SKILL.md)

## 五、把闭环扩展到实时世界和多主体

### 16. 实时交互的核心是提交边界

**它解决什么问题**：把回合式 Agent 接上流式语音或事件队列，并不会自动获得低延迟、可打断和可恢复能力。

**核心逻辑**：区分 partial 与 final 输入、草稿与已提交输出、可撤销与不可撤销动作；为用户抢话、慢工具、后台任务、取消和恢复建立事件协议。级联语音基线把 VAD、ASR、LLM、TTS 每段延迟分别记录，便于定位；端到端音频与自级联的小样本对照则表明，架构标签不能代替任务实测。异步邮件案例进一步说明，占位符只能表示 pending，真实完成必须由事件确认。

**什么时候会失效**：递增前缀反复编码不等于真流式；未定义提交点时，模型可能在用户尚未说完或页面已变化时执行不可逆动作。

→ 深入：[`design-realtime-agent-interactions`](../../skills/ai-agent/interaction-collaboration/design-realtime-agent-interactions/SKILL.md)

### 17. 行动闭环要按时间尺度分层

**它解决什么问题**：高层模型若逐帧控制 GUI 或机器人，会慢且脆弱；低层技能若盲目执行长动作块，又会错过环境变化。

**核心逻辑**：目标层决定成功与硬约束，规划层选择子任务，技能层执行受限动作块，控制层处理高频反馈；每个动作块后重新观察并验收。Computer Use 遇 CAPTCHA 后切换网站，说明计划必须接受新观察而不是回放到底；XLeRobot 从人类遥操作、模拟器、真机 Agent、模拟闭环到域随机化逐层验证，避免把仿真成功当成真机完成。代码和文件系统则是数字任务中的技能核，把开放目标落成可验证工件。

**什么时候会失效**：分层过多会增加延迟和接口错误；动作边界不可观察、技能没有完成条件时，只是把同一混乱拆进多个模块。

→ 深入：[`build-multiscale-action-loops`](../../skills/ai-agent/interaction-collaboration/build-multiscale-action-loops/SKILL.md)

### 18. 多 Agent 的价值来自信息增量，不是角色数量

**它解决什么问题**：把同一个输入交给多个同质模型轮流改写，通常只增加 token 和错误链，却被包装成“协作”。

**核心逻辑**：先建立同预算单 Agent 或确定性基线，再要求每个候选角色证明至少一种增量：独立外部观察、异源验证、隔离权限或真并行结果。随后才根据依赖图选择 Manager、去中心化路由或 fan-out，并为每条边定义自包含输入、结构化产物、所有者、验收、预算、取消和冲突裁决。PPT 审核因看到了渲染新模态而有效；十网站搜索因外部状态独立而从约五分钟缩短到十九秒；狼人杀的代码裁判和受限上下文则展示信息与权限隔离。

**什么时候会失效**：二十个参数与汇总规则都固定的 REST 请求只需要普通并发队列；角色共享同一盲区、子任务强依赖隐式状态或 Manager 无法验收时，应退回单 Agent 或确定性流程。

→ 深入：[`design-multi-agent-collaboration`](../../skills/ai-agent/interaction-collaboration/design-multi-agent-collaboration/SKILL.md)

## 陷阱与反例

### 1. 把模型自报完成当成环境成功

模型说“退款已处理”只是轨迹中的一句话。若数据库状态、退款编号或权限日志没有变化，任务仍然失败。预警信号是评估只读最终文本、不读取工具结果和环境快照。修复方式是把不可伪造的外部后置状态写进工具契约和 Rubric。

### 2. 用 Top-k 检索回答全集统计

向量检索优化的是相关性，不是全集覆盖。用最相关的几十条推断“所有地区总额”会产生系统性漏算，重排再精确也无济于事。预警信号是问题要求枚举、计数或聚合，而方案仍只有 Top-k。此时应转结构化查询、全量扫描或预计算摘要。

### 3. 为长上下文反复做摘要套摘要

摘要会丢失失败路径、来源和因果关系；摘要再摘要会让错误变得不可恢复。预警信号是压缩后 Agent 无法回答约束来自哪一轮，或重复已经造成副作用的动作。先隔离不必共享的轨迹，剩余摘要保留目标、约束、决策理由、失败证据和恢复指针。

### 4. 对所有错误统一重试

超时可能恢复，参数错误、权限拒绝和前置条件不满足通常不会。统一退避会制造重试风暴，非幂等操作还会重复扣款。预警信号是同一参数、同一错误码连续出现且环境无进展。失败分类、幂等键、预算、熔断和人工出口必须在 Harness 中显式化。

### 5. 让模型修改自己的验证器

一旦候选策略能删除测试、放宽成功门槛或伪造工具结果，奖励和持续进化就失去可信根。预警信号是“自我改进”提交同时包含策略、测试和发布配置。正确结构是候选只提案，隐藏测试、稳定版本、审批与回滚由外部权限域掌握。

### 6. 用多角色讨论替代独立证据

多个 Agent 使用相同模型、输入和提示互相点评，往往共享同源偏差。预警信号是无法回答“去掉这个角色会失去什么新观察或权限边界”。没有可验证增量时，使用单 Agent、确定性检查器或一次真正独立的工具验证更便宜也更可靠。

## 作者的局限：读这本书要打的折扣

1. **案例高度依赖当前技术阶段**。书中大量材料来自 2025 至 2026 年的头部模型、MCP、Skills、全双工音频、VLA 和可编辑上下文研究。架构原则较稳定，但具体性能数字、产品边界和实现手法可能很快过时。
2. **高风险长流程业务的经验可能诱导过度设计**。作者的工程立场强调 Harness、异步自治和复杂验证，这对 Pine 一类任务合理；低风险、短流程、强确定性业务却可能用普通程序更便宜、更可审计。
3. **自动评估仍可能同源偏置**。LLM Judge、模型生成的仿真环境和自动归因即使可复现，也不保证与真实业务价值一致。书中提供了治理方向，但没有消除数据泄漏、标注偏差和评判器被优化的问题。
4. **多 Agent 和持续进化的长期净收益证据仍有限**。局部案例能证明机制可行，却不足以证明跨组织、跨模型和长期负载下收益持续大于协调、维护、安全与回归成本。

最强的反对意见是：许多 Harness 复杂性只是当前模型不可靠的过渡补丁。这个质疑值得保留。更强模型可能吸收部分提示、工具选择和流程能力，传统软件也可能覆盖大多数固定业务。书中最有价值的回应不是“Harness 永远更多”，而是把复杂度放在模型尚未可靠覆盖、且收益能被评估证明的边界上；其余部分应主动退回更简单的系统。

## 关键术语速查

| 术语 | 作者的用法 | 和常见说法的差异 |
|---|---|---|
| Agent | LLM、上下文与工具构成的自主决策系统 | 不是单独的聊天模型或提示词 |
| 上下文 | 每个决策点模型能看到的全部信息 | 不只是聊天记录，也包含工具定义、结果和状态 |
| 工具 | Agent 感知或改变外部世界的接口 | 不只指函数 API，也包括观察、协作和消息通道 |
| ReAct 循环 | 思考、行动、观察结果后继续决策 | 重点是反馈闭环，不是输出显式思维链 |
| Harness | Agent 边界内、模型之外的运行与治理层 | 不是薄封装，也不是外部 Environment |
| 轨迹 | 运行中累积的消息、调用和工具结果 | 不等于环境最终结果 |
| Agent Skill | 有触发条件、可按需加载的领域操作手册 | Skill 说明如何做，工具提供能做什么 |
| Agentic RAG | Agent 自主决定检索、改写、继续和停止 | 不等于每次回答前固定向量检索 |
| Pass@k | k 次尝试中至少一次成功 | 衡量能力上限，不证明连续可靠 |
| Pass^k | 连续 k 次全部成功且无否决项 | 面向生产稳定性，不是“多试几次挑最好” |
| 失败归因 | 找到首个使任务偏离的因果错误 | 不是把最后异常或全部症状当根因 |
| 持续进化 | 候选经验经验证、发布和回滚后进入正式系统 | 不等于生产中无限制在线自我修改 |

完整词典见 [GLOSSARY.md](./GLOSSARY.md)。

## 如果只带走三句话

1. Agent 的能力边界同时由模型策略、可见信息和可执行动作决定；遇到失败，先定位观察、策略、动作或反馈的首个断点，不要默认换模型。
2. 生产可靠性来自可验证的 Harness：权限、状态、故障闭环、外部真值和可复现评估必须围绕概率性决策建立硬边界。
3. 经验只有进入正确载体并经过独立验证、灰度与回滚，才叫进化；更多上下文、更多 Agent 或更多训练都不是默认答案。
