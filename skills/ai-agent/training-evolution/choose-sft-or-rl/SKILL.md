# 先外部修复、再 SFT 固形、后 RL 塑策

## R — 原文 (Reading)

> SFT 先把“形” （格式、结构）立起来，RL 再追求“神” （策略、泛化） ，即先形后神。

来源：第 7 章 7.1.3 “什么时候需要先 SFT 后 RL”，PDF 第 204 页。

## I — 内化 (Internalization)

SFT 与 RL 不是两个可以脱离故障类型直接比较的训练按钮。先定位缺口位于外部表达层、输出协议层，还是需要探索的策略层。

若错误能由增加上下文、纠正工具反馈、收窄动作空间、加入确定性校验或局部 Prompt 规则解决，优先外部修复。这些改动可追溯、可局部编辑、可灰度、可回滚，通常比改参数便宜。

SFT 最大化示范 token 的似然，擅长稳定格式、术语、调用协议、基础行为与表达风格；它也可能复现训练分布中的表面捷径，不能仅凭训练集拟合断言学会了规则。

RL 通过环境交互最大化期望奖励，适合无法逐步示范、需要试错、延迟反馈或组合泛化的策略。但 RL 的前提是动作可解析、环境足够可信、奖励确实对应目标且违规路径不可钻空子。

顺序不是教条，而是门槛：先让 Harness 与 SFT 提供可运行、可解析的策略基线，再让 RL 在有效轨迹上探索；若外部修复已经达到验收标准，就停止，不为“用了训练”而训练。

## A1 — 作者案例 (Author's Cases)

### 案例 1：航空客服 Prompt 消融

- **问题**：怎样判断一次失败是否真的需要改模型参数？
- **方法**：固定模型与任务，只改变语气、结构和规则组织方式，比较实验 2-4 的任务成功率。
- **结论**：语气变化影响很小，打乱规则组织却使成功率下降超过 30%，说明不少能力缺口首先是上下文可表达性问题。
- **结果边界**：该实验支持先做 Prompt/Harness 消融，不证明所有领域都能靠提示词解决。

### 案例 2：GeneralPoints 的 SFT 与 RL

- **问题**：模型应复现示范，还是学会跨数字组合的规则？
- **方法**：在严格格式任务上比较 SFT、RL 及分布外样本；同时观察小模型不经 SFT 直接 RL 的训练稳定性。
- **结论**：SFT 在该实验的分布外集合上均下降，RL 带来改善；但小模型因格式不稳直接 RL 会完全失败。
- **结果边界**：这是小规模受控结果，支持“先形后神”的门槛，不可外推为 SFT 必然不泛化或 RL 必然优于 SFT。

### 案例 3：带来源的最小 Prompt 补丁

- **问题**：一条生产失败经验应否直接触发后训练？
- **方法**：把错误归因到明确边界，只增加带来源的局部规则，并在目标 canary 与旧任务回归上验证。
- **结论**：实验 8-3 只在边界任务改善且旧任务无回归后接纳补丁，展示了参数更新前更便宜、更可逆的路径。
- **结果边界**：单个补丁成功不能说明长期规则堆叠可无限扩展；复杂度上升后仍需重新评估载体。

## A2 — 适用场景 (Application)

### 何时调用

1. 用户在 Prompt、上下文、工具、SFT 和 RL 之间选择最小修复路径。
2. 输出 JSON、tool call 或固定结构不稳定，正在判断应先做监督微调还是强化学习。
3. SFT 训练集表现好但组合变化、分布外任务或真实交互中退化。
4. 已有基础 Agent，需要决定某类失败是局部规则、协议习惯还是探索策略问题。
5. 收到 “SFT or RL”, “fine-tuning vs reinforcement learning”, “post-training strategy”, “prompt or fine-tune”等英文请求。

### 语言信号

- 中文：“该微调还是强化学习”“先 SFT 还是直接 RL”“Prompt 已经改不动了”“格式学会了但不会策略”“要不要把这个行为训进参数”。
- English: “Should we use SFT or RL?”, “prompt engineering or fine-tuning?”, “format is stable but policy does not generalize”, “direct RL or SFT warm start?”.

### 与相邻 Skill 的区分

- `route-agent-updates` 决定知识、指令、程序、参数四种**持久载体**；本 Skill 在参数训练被证明必要后，进一步选择 SFT/RL，并保留外部修复优先门槛。
- `design-verifiable-agent-rewards` 设计 RL 的奖励与违规路径门控；本 Skill 只决定是否进入 RL，不替代奖励工程。
- `govern-continuous-agent-evolution` 管理生产经验如何离线形成候选版本；本 Skill 管理某个已确认能力缺口的训练方法。

## E — 执行步骤 (Execution)

**执行硬门：** 在失败可复现、动作可解析性已测量且外部可修复性消融完成前，不得收集训练样本、选择 SFT 或设计 RL；若外部修复达标，立即停止后训练选型。

### 1. 写出单一可复现实例

固定模型、版本、输入、工具状态、期望输出与实际输出，把“效果不好”改写为一个可重复失败。

- **完成标准**：同一基线至少复现 3 次，且失败判据可由解析器、测试或明确人工标注判断。
- **判停点**：无法复现或目标本身没有验收标准时停止选型，先补评测。

### 2. 做外部可修复性消融

依次测试：补充必要上下文、纠正工具结果、收窄权限与动作空间、局部 Prompt 规则、确定性程序/校验器。每次只改一个因素。

- **完成标准**：记录每个变体的目标成功率、旧任务回归、延迟和成本，能判断哪一层造成变化。
- **判停点**：任一可逆外部修复达到目标且旧任务无回归时停止，不进入后训练。

### 3. 判定缺口类型

将剩余问题归类为：格式/术语/协议/基础习惯，或需要探索、延迟反馈、组合泛化的策略。可变事实与私有知识单列，不进入参数训练。

- **完成标准**：每个错误样本只有一个主类，并附为何不能用更外层载体表达的证据。
- **判停点**：若目标是记忆政策、价格、接口或私有事实，停止训练，转知识库/RAG。

### 4. 建立 SFT 协议基线

对格式与基础行为准备高质量示范；只对策略可控 token 计算损失，屏蔽用户、工具和环境返回；划分格式集、同分布任务集与组合/OOD 集。

- **完成标准**：目标动作可解析率达到预设门槛，基础任务成功率不低于基线，且 OOD 指标没有越过回归阈值。
- **判停点**：训练损失下降但留出集连续恶化，或模型开始编造环境返回时早停并检查数据与 loss mask。

### 5. 检查 RL 准入条件

确认环境可复位、奖励器不可由策略修改、结果信号可靠、违规路径有独立否决、模拟器偏差有真实校准集。

- **完成标准**：一批人工审计轨迹中，奖励排序与真实任务质量一致；格式失败不再主导零奖励；至少有一个真实或高保真留出环境。
- **判停点**：奖励可被删测试、改验证器或违规动作劫持，或环境无法复位时停止 RL，转入奖励/环境修复。

### 6. 小步比较并选择

在相同数据预算、交互预算和评测集上比较外部修复、SFT、SFT+RL；同时报告成功率、解析率、违规率、OOD、成本与延迟。

- **完成标准**：只有当更复杂方案在主指标上超过预设最小收益，且安全与旧任务指标全部过门，才选用它。
- **判停点**：收益不能覆盖训练、服务和回滚成本，或只在训练环境改善时，保留较简单方案。

## B — 边界与禁区 (Boundary)

### 不要在以下情况使用

- 高频变化、要求来源或需要精确撤销的事实：用版本化知识库/RAG，不把事实写进参数。
- 任务步骤可完全枚举且确定性程序更便宜：直接实现工作流或程序。
- 没有可重复评测、可靠环境或奖励：不能用训练替代问题定义。
- 只需选择 LoRA、训练平台、优化器或 GPU：这属于训练实现选型，不是本 Skill 的方法决策。

### 明确反例与警告

- **ce074 表面捷径**：有限同质示范让 SFT 学到格式相关性，训练损失下降而 OOD 退化。
- **ce075 顺序错误**：结构化动作未稳定就 RL，rollout 被解析失败截断，奖励全零或失真。
- **ce076 载体错配**：用后训练记忆可变事实，导致来源不可追溯、更新慢且难撤销。
- **ce077 模拟器上限**：RL 学会模拟器漏洞，仿真高分不等于真实部署有效。
- **ce078 主体污染**：把 tool result/user token 也作为训练目标，模型会倾向编造环境输出。

### 阶段 0 批判边界

- 书中 SFT/RL 结论主要来自小规模受控实验，模型、任务和奖励分布变化后必须重做对照，不能把“先形后神”当成无条件规律。
- 书中工程路线建立在 2025-2026 年自回归模型、tool call 与 Harness 假设上；更强的原生交互模型可能改变格式预热的成本收益。
- 作者偏重高风险、长流程和软件任务，容易高估复杂 Harness 与后训练流水线；短、低风险、规则明确任务应默认普通程序。
- 小团队未必有高保真模拟器、足够 rollout 或独立验证器。资源不足时应缩小目标或停在可逆外部修复，而非做低质量 RL。
