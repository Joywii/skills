# 知识-指令-程序-参数四载体路由

## R — 原文 (Reading)

> 选择更新方式的首要依据不是经验出现了多久，而是目标能力能否被某种载体自然表达。

来源：第 8 章 8.2 “Agent 持续进化的四种方法”，PDF 第 241 页。

## I — 内化 (Internalization)

同一条生产经验可以被写成检索条目、Prompt/Skill 规则、确定性程序或参数更新，但四种实现的可编辑性、验证性、回滚成本和适用范围完全不同。

**知识**表达“世界是什么”：事实、案例、政策、来源和版本。它适合频繁变化、需要引用和局部撤销的内容。

**指令**表达“遇到某类情形应怎么做”：工作原则、步骤、边界和检查表。它适合可由语言清楚说明、需要人审和快速迭代的策略。

**程序**表达确定性、重复执行且必须不可绕过的约束：解析、计算、校验、状态机、权限和安全门。它适合可形式化、可测试的行为。

**参数**承载难以通过外部载体自然表达的统计习惯、感知、风格、协议熟练度和复杂策略。它最难局部编辑、解释和回滚，因此是最后选择而非“更高级”的选择。

路由依据不是经验出现一次还是一百次，而是目标能力的表示形式，以及生产要求的可编辑、可验证、可追溯、可逆四项属性。必要时可以分层组合，但每一层必须有独立职责。

## A1 — 作者案例 (Author's Cases)

### 案例 1：从法律案例形成可追溯知识

- **问题**：大量判例中的事实要素如何复用，而不把每次摘要写入模型参数？
- **方法**：实验 3-12 让模型提取要素、形成原型与聚类，并用主动追问补齐信息；原案例保持为证据来源。
- **结论**：事实与案例模式适合进入可检索、可追溯的知识载体。
- **结果边界**：聚类和摘要是可重建派生物，不能替代已审核的原始证据。

### 案例 2：代码验证航空政策

- **问题**：复杂参数规则仅靠自然语言指令容易漏项或算错。
- **方法**：实验 5-3 用 Prompt 指明决策流程，以参数检查表约束输入，再由服务器真实逻辑计算最终状态。
- **结论**：规则说明可放指令，精确计算与真值判断应放程序；组合载体比全塞进 Prompt 更可靠。
- **结果边界**：案例给出预期行为与工程方法，不是大规模线上数值基准。

### 案例 3：语音协议的 SFT

- **问题**：音色克隆、非语言标记和副语言控制难以仅靠运行时文字规则稳定表达。
- **方法**：实验 7-6 用 SFT 学习表达协议与控制行为。
- **结论**：当能力是分布式的表达习惯而非可枚举知识或规则时，参数载体有其位置。
- **结果边界**：少说话人或僵硬标记会过拟合；该结果不支持用参数存储可变事实。

## A2 — 适用场景 (Application)

### 何时调用

1. 把复盘得到的经验转成长期可复用更新，需要选择存放位置。
2. 在 RAG/知识库、Prompt/Skill、代码/工作流、SFT/RL 之间做架构决策。
3. 现有 Prompt 膨胀、知识漂移、规则被绕过或参数事实过期，需要迁移载体。
4. 同一能力包含事实、流程和硬约束，需要拆成多层而非选一个万能载体。
5. 收到 “where should this update live?”, “knowledge vs instructions vs code vs weights”, “prompt, RAG, program or fine-tune?” 等英文请求。

### 语言信号

- 中文：“这条经验写到哪里”“该进知识库还是 Skill”“规则要不要写代码”“为什么不直接微调”“怎样让更新可回滚”。
- English: “route an agent update”, “put it in RAG or weights”, “instruction versus deterministic code”, “editable and reversible behavior update”.

### 与相邻 Skill 的区分

- `choose-sft-or-rl` 处理参数载体内部的 SFT/RL 选择；本 Skill 先判断是否根本需要参数载体。
- `govern-continuous-agent-evolution` 规定证据如何离线形成候选、验证和发布；本 Skill 只决定候选更新的承载形式。
- `design-trusted-agent-tools` 设计可靠工具契约与权限；本 Skill 只在“程序”被选中后指出应外部化，不展开具体工具设计。
- `attribute-first-errors` 先归因故障层；本 Skill 根据已确认根因选择持久更新载体。
- `build-evidence-backed-memory` 只承接已选中的知识载体，处理来源、冲突与版本；本 Skill 不负责知识内部的写入生命周期。

## E — 执行步骤 (Execution)

**执行硬门：** 在更新被原子化为“触发条件、期望行为、例外、来源”并绑定可观察结果前，不得判断知识、指令、程序或参数载体。

### 1. 把经验改写为目标能力

删除会话叙事，写成“在什么条件下，需要知道什么/遵循什么/计算什么/表现出什么能力”，并附成功、失败和部分成功证据。

- **完成标准**：目标句含触发条件、期望行为、例外和来源，且能指出此次更新试图改变哪一个可观察结果。
- **判停点**：只有一次无验证的成功或失败，无法区分因果与偶然时，不形成正式更新。

### 2. 判断自然表示形式

依次提问：它是带来源且会变化的事实吗？是可清楚书写的操作原则吗？是可形式化且必须一致执行的规则吗？还是外部载体难以表达的统计能力？

- **完成标准**：选出一个主载体，并用一句话解释为何其表示形式比另外三种更自然。
- **判停点**：若一条更新同时混合事实、流程和约束，先拆成原子更新，不做整包路由。

### 3. 以四项属性复核

为知识、指令、程序、参数分别评分：局部可编辑性、独立可验证性、来源可追溯性、版本可逆性；同时估计运行时成本和覆盖范围。

- **完成标准**：主载体满足所有硬性属性；若不能，记录补偿层，例如“指令说明 + 程序硬门禁”。
- **判停点**：需要精确撤销或提供来源却选择参数，或不可绕过却只选择自然语言指令时，拒绝该路由。

### 4. 选择最外层有效载体

按知识/指令/程序等外部载体先行、参数后置的原则制作最小 diff。不要为一个局部边界重写整份 Prompt、知识或程序。

- **完成标准**：diff 仅覆盖触发证据对应范围，带来源、版本、负责人和回滚动作。
- **判停点**：较外层载体已在目标任务通过且无回归时停止，不升级到更难回滚的载体。

### 5. 为载体建立专属验证

知识查来源与时效；指令测触发、遵循和冲突；程序跑单元/集成/权限测试；参数测格式、能力、OOD、安全与旧任务回归。

- **完成标准**：目标 canary 改善、全部硬约束通过、旧任务未越过回归阈值，且能从结果追到更新版本。
- **判停点**：只有整体平均分、无法归因到载体变更时，不发布。

### 6. 记录组合边界并交付发布治理

若采用多载体，明确事实真源、决策顺序与冲突优先级；生成更新清单、验证证据、canary 计划和回滚包。

- **完成标准**：任一运行时冲突都能由确定优先级裁决，且删除某层时预期退化可被测试捕获。
- **判停点**：两个载体重复保存同一真值且无同步协议时，停止发布并指定唯一可信源。

## B — 边界与禁区 (Boundary)

### 不要在以下情况使用

- 根因尚未定位：先做错误归因，不要用载体选择掩盖工具、上下文或环境故障。
- 只是在编辑一篇普通文档或分类文件：这不是 Agent 能力更新。
- 已确定必须参数训练，只需选择 SFT/RL：转 `choose-sft-or-rl`。
- 需要定义在线/离线循环、审批、灰度和回滚责任：转持续进化治理。

### 明确反例与警告

- **ce034 摘要漂移**：用摘要更新摘要使有损错误代际累积；知识真源必须是原始证据。
- **ce063 空白自举**：让 Agent 从零生成完整 Agent，隐性架构约束缺失且错误会跨代积累。
- **ce076 参数记事实**：政策、价格和接口写进参数后难引用、难更新、难撤销。
- **ce086 全量重写**：局部经验触发整份 Prompt/记忆重写，会丢失旧规则并破坏归因。
- **ce090 指令当安全边界**：可被绕过的自然语言不能代替权限检查、状态机或程序验证。

### 阶段 0 批判边界

- 四载体是工程抽象而非互斥自然定律；检索增强模型、可编辑参数、程序合成等新技术会模糊边界，仍需回到四项属性实测。
- 书中方案依赖 2025-2026 年 Prompt、Skill、RAG、SFT/RL 栈，具体载体成本可能快速变化。
- 作者偏重软件、Python、文件系统与高风险长流程，因此倾向可审计外部载体；低风险创意表达可能更适合参数化习惯而非复杂治理。
- 案例多展示成功路径，缺少长期维护成本和大规模控制组；组合层越多，集成复杂度也可能抵消可编辑收益。
