# 构建可复现的 Agent 评估系统

## R — 原文 (Reading)

> 结果与过程是硬门，只有都通过时，语言质量才有资格决定候选是否值得学习。
>
> — 李博杰，第 8 章 8.1「从运行轨迹中获得学习信号」，PDF 第 241 页

---

## I — 方法论骨架 (Interpretation)

Agent 评估的对象是 Model 与 Harness 的组合，不是脱离工具和环境的单条回复。
一套评估循环至少需要任务数据集、可验证初始状态、可重置环境、原子工具/交互协议和评分器。
先定义成功，再建设环境与数据；否则团队会用现有日志能测到的东西代替真正业务目标。
结果层读取数据库、文件、测试或环境状态，回答“事情是否真的办成”；这是第一硬门。
过程层检查权限、业务规则、动作顺序和危险捷径，回答“是否以允许方式办成”；这是第二硬门。
质量层评价完整性、表达、帮助性等软目标，只在结果与过程通过后评分，不能抵消失败或违规。
能由确定性代码判断的内容优先用验证器；开放式质量再使用带具体档位的 Rubric 和经人工金标校准的 Judge。
人机交互任务必须模拟渐进式信息透露与双向状态变化，不能一次把所有答案塞给 Agent。
每次运行保存任务版本、模型/Harness/工具版本、完整轨迹、最终状态、评分证据、成本和随机种子。
评估数据要分任务族、风险和失败簇报告，并严格隔离训练集、开发集、边界集、保留集和最终评估集。

## A1 — 书中的应用 (Past Application)

### 案例 1：退款客服四维 Rubric
- **问题**: 一段客服回复看似合理，但可能订单状态、政策、到账信息或工具依据任一项错误。
- **方法论的使用**: 作者用三天前 299 元耳机退款轨迹，逐项核对订单、政策、到账与工具结果，并把幻觉设为否决项。
- **结论**: 评分维度要落到可观察事实，而不是用“回答很好”概括。
- **结果**: 示例四维均通过，订单、金额、时间和退款编号都有工具证据，没有触发幻觉否决。

### 案例 2：τ²-bench 双控制评估
- **问题**: 客服 Agent 既与用户对话又改变订单环境，单轮静态问答无法验证信息收集和真实状态变化。
- **方法论的使用**: 实验 6-1 使用用户模拟器按脚本渐进透露信息，并同时检查数据库目标状态和对话中必需确认。
- **结论**: 人机交互评估要控制用户与工具环境，结果与协议缺一不可。
- **结果**: 实验输出政策违规、信息遗漏和过度转人工等失败分析，而不是只给最终自然语言分数。

### 案例 3：客服轨迹三层验证器
- **问题**: 单一总分不能区分任务失败、违规、虚假承诺与表达质量，也无法指导修复载体。
- **方法论的使用**: 实验 8-1 对照总分验证器与逐维度输出结论、证据、置信度的结果/过程/质量验证器。
- **结论**: 学习信号必须可归因，低置信度结果不能自动进入学习集。
- **结果**: 实验以诊断可分辨性作为验收，明确只有结果和过程硬门通过后才讨论语言质量。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 新 Agent 准备选模型、改 Prompt/Harness 或上线，但没有可重复的自有任务集。
2. 当前评估只看最终回复，无法确认数据库、文件、邮件、订单等环境状态是否真的变化。
3. 最终结果正确但过程可能越权、删测试、绕规则，需要不可被平均分抵消的安全硬门。
4. 开放式报告、客服、语音或多模态输出需要 LLM Judge，但尚无 Rubric 和人工金标校准。
5. 评估结果随运行顺序、残留状态、模型版本或 Judge 更新漂移，无法公平比较。

### 与相邻 Skill 的区分

- 与 `measure-capability-vs-reliability` 的区别: 本 skill 构建可信评估循环和证据；双指标 skill 在此基础上选择 Pass@k 或 Pass^k 并解释业务含义。
- 与 `attribute-first-errors` 的区别: 本 skill 产出可重复任务、轨迹和评分；首错归因使用这些资产定位具体失败并做局部回归。
- 与 `formalize-and-verify-agent-work` 的区别: 形式化 skill 为单个任务建立确定执行与验收；本 skill 管理任务分布、环境、Judge、统计与版本比较。
- 与 `design-verifiable-agent-rewards` 的区别: 本 Skill 的评分用于测量和比较；后者把其中可优化的信号暴露给策略，因此还必须审计信息泄漏、路径合法性和 reward hacking。
- 与 `build-independent-review-loops` 的区别: 本 Skill 建设跨样本评估基础设施；后者是在单次生成或发布路径中用异源证据做提议-退回闭环。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **写成功契约与分层门槛**
   - 为每类任务定义初始状态、用户目标、真实结果、允许/禁止路径、软质量、成本和安全否决项。
   - 完成标准: 结果、过程、质量三层分别可判；结果或过程失败不会被质量高分抵消。
   - 判停条件: 若业务方无法说明“完成后环境应变成什么”，先澄清目标，不要用流畅回答代理成功。

2. **建设可验证重置环境**
   - 提供 `reset/step/observe/final_state` 等接口，固定依赖、时间与账号；每轮检查初始状态哈希或关键断言。
   - 完成标准: 同一任务重复启动得到相同初始状态；交换执行顺序不改变基线结果。
   - 判停条件: 任一任务无法干净重置时，标记环境无效并停止模型比较，不能把污染归因给 Agent。

3. **定义原子工具与交互协议**
   - 工具暴露可观察动作而非“解决问题”高层捷径；用户模拟器只按脚本渐进透露信息，并记录双向状态变化。
   - 完成标准: Agent 无法直接读取隐藏答案；工具结果和用户信息都能在轨迹中复核；协议覆盖澄清、拒绝和转人工。

4. **构造分层数据集并人工走查**
   - 覆盖简单/中等/困难、正常/边界/对抗、成功/失败、高风险任务族；由人亲自完成代表用例并记录歧义。
   - 完成标准: 每个能力与风险维度有任务；任务可由合格人类在环境中完成；训练、开发和最终评估实例隔离。

5. **实现三层评分器**
   - 结果优先用数据库断言、测试、状态 diff；过程检查权限与动作；质量用具体验收档位的 Rubric 和 Judge。
   - 完成标准: 每个评分附证据位置；安全/幻觉为 veto；Judge 不负责本可确定验证的事实。

6. **校准 Judge 与验证器**
   - 建人工金标集，测一致率、边界分数、误拒/漏放、长度与位置偏差；模型或 Rubric 变更后重校准。
   - 完成标准: 披露一致性与分歧处理；低置信度或高风险分歧转第二评委/人工，而非自动放行。

7. **执行、保存和分层报告**
   - 多个固定种子运行，保存版本、完整轨迹、最终状态、逐层评分、证据、延迟与成本；按任务族和失败簇报告。
   - 完成标准: 任一分数可回溯到原始运行；报告包含样本量和波动，不只有 overall score。

8. **把失败回流成回归资产**
   - 对生产 bad case 脱敏、归因，加入端到端或轨迹前缀回归；修复后同时运行边界、保留和安全集。
   - 完成标准: 每次系统变更都有对应回归证据，且没有把评估实例重新泄漏进训练后继续充当独立测试。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 只是一个纯确定性函数，现有单元测试已完整覆盖输入输出，不需要 Agent 级环境和轨迹评估。
- 只需决定 Pass@k 与 Pass^k 的报告方式，环境、数据和验证器已经可信；使用指标选择 skill 即可。
- 当前是在处理线上事故，首要任务是止损与恢复；先执行故障闭环，随后再把事故沉淀为评估用例。

### 作者在书中警告的失败模式

- 只看回复、轨迹或最终状态的一侧，会分别漏掉假完成、违规捷径或真实失败（ce065）。
- LLM Judge 未经人工金标校准就放量，分数只是“另一个模型的意见”（ce066）。
- Rubric 只奖励流畅、篇幅和关键词，事实与专业风险未进入评分，诱发奖励作弊（ce067）。
- 训练数据泄漏进评估集，分数测到的是记忆而非泛化（ce068）。
- 环境无法干净重置，前一轮状态和运行顺序污染下一轮（ce073）。
- 结果奖励允许删测试、改验证器或违规捷径，最终分数提高却破坏真实目标（ce079）。

### 作者的盲点 / 时代局限

- LLM Judge、模型模拟环境和自动失败归因可能共享同源偏差；流程可复现不保证结论真实或与业务价值一致。
- 评估体系依赖头部模型、仿真环境、标注和运维资源，中小团队可能无法一次复现完整闭环。
- 全书偏软件和工具调用任务，组织影响、长期用户体验、合规责任与延迟外部性需要额外人工评价。
- 2025-2026 的 benchmark 与产品接口变化快，应保留方法骨架，避免把具体榜单或框架实现固化为标准。

### 容易混淆的邻近方法论

- 可重复不等于有效：稳定测量错误代理目标，仍会稳定地产生错误结论。
- 自动评估不等于无人监督：金标校准、任务定义和高风险分歧仍需领域专家。
- 结果、过程和质量不是三个可互相补偿的平均分；前两者是硬门，质量是其上的软排序。
