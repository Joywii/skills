# 观察-策略-动作-反馈四面诊断

## R — 原文 (Reading)

> 没有通过观察通道进入上下文的信息，对模型来说就像不存在；没有被动作接口允许的操作，模型即使知道该怎么做，也只能停留在文字建议上。
>
> — 李博杰，第 1 章 1.1.1「观察空间与动作空间：模型与世界的接口」，PDF 第 16 页（书内第 8 页）

---

## I — 方法论骨架 (Interpretation)

Agent 的一次决策不是模型单独完成的，而是四个因果槽串联的结果：

1. **观察**：任务所需事实是否以正确、及时、完整的形式进入当前上下文。
2. **策略**：在可见事实与可选动作都正确时，模型是否选择了合适的下一步。
3. **动作**：系统是否真的提供了所需工具、参数、权限和执行适配器。
4. **反馈**：动作结果是否带身份与状态写回下一轮，让策略能修正旧假设。

任何前槽断裂，后槽表现都会失真。例如工具结果未回流会表现为“模型不会停止”，缺权限会表现为“模型只会解释”。诊断因此必须沿链路从前往后取证，不能先换模型。每个结论都应指向一个可复现的断点和一个最小修复，而不是归结为模糊的“智能不足”。

## A1 — 书中的应用 (Past Application)

### 案例 1：上下文四组件消融（c001）
- **问题**：完整 ReAct 任务失败时，很难判断系统提示、工具定义、工具结果、思考和历史各自贡献了什么。
- **方法论的使用**：作者固定任务与模型，逐项移除上下文组件，观察哪类能力首先消失。
- **结论**：工具定义决定可选动作，工具结果决定反馈闭环，历史维持已完成状态，决策过程维持前后协调。
- **结果**：缺工具定义时无法行动；缺结果时反复调用；缺历史时重做已完成步骤；缺决策过程时出现矛盾。

### 案例 2：XLeRobot 五阶段闭环诊断（c091）
- **问题**：杯子与废纸归位失败，可能来自硬件、感知、规划、控制、恢复或仿真迁移，不能笼统归因于机器人模型。
- **方法论的使用**：保持摄像头、机械臂、桌面布置和成功条件不变，依次用真人闭环、理想模拟器、真机 Agent 与随机化模拟替换链路组件。
- **结论**：真人遥操作能成功，说明硬件动作空间足够；后续差距应继续在策略、反馈和迁移环节定位。
- **结果**：实验把“硬件不可行”排除，并明确模拟成功不能替代真机新观察的验收。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. Agent 拿不到明明存在的数据，或基于过期、截断、错误对象的数据决策。
2. Agent 能解释正确做法，却没有调用工具、因缺权限失败，或实际参数与模型所见不同。
3. 工具已经成功，但 Agent 重复执行、声称没有结果或过早宣告完成。
4. 团队准备通过换模型、加提示词或加重试修复生产 bad case，但尚未定位故障层。

### 语言信号 (用户的话里出现这些就应激活)

- “到底是模型不够聪明，还是上下文/工具有问题？” / “model issue or harness issue?”
- “它明明知道怎么做，为什么不执行？” / “why can't the agent act?”
- “工具已经返回了，为什么还在循环？” / “tool result exists but the agent keeps looping”
- “帮我做 observation-policy-action-feedback / OPAF root-cause analysis”

### 与相邻 Skill 的区分

- 与 `choose-agent-autonomy` 的区别：本 skill 诊断**现有系统的具体失败**；后者在实现前或重构时选择单调用、工作流或自主 Agent。
- 与 `build-reproducible-agent-evals` 的区别：本 skill 找故障所在因果槽；后者设计可重复评估环境与评分硬门。
- 与 `build-multiscale-action-loops` 的区别：本 skill 是通用边界诊断；后者专门设计 GUI/机器人多时间尺度动作闭环。
- 与 `attribute-first-errors` 的区别：故障层仍未知时先用本 Skill 划定观察、策略、动作或反馈断点；已有首错候选与可重放轨迹时，再由后者做因果验证。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **冻结失败样本与外部验收**
   - 保存任务输入、模型/提示版本、完整轨迹、工具日志和最终环境状态；把“真正完成”写成可观察断言。
   - 完成标准：同一初始状态下能复现失败，且完成标准不依赖模型自报。
   - 判停条件：若无法复现或没有环境证据，停止归因，先补可观测性。

2. **审计观察面**
   - 列出作出正确决策所需的事实，并逐项对照模型当轮实际可见内容；检查缺失、过期、截断、权限过滤和对象错配。
   - 完成标准：形成“必需事实 → 来源 → 当前上下文位置 → 版本/时间 → 是否完整”的证据表。
   - 判停条件：发现关键事实未进入或错误进入上下文时，标记 `observation` 为首个断点，跳到步骤 6。

3. **审计策略面**
   - 在观察与动作定义均完备的同一前缀上重放决策；检查模型是否选错工具、拒绝行动、忽略约束或错误停止。
   - 完成标准：能指出第一个不合理决策及当时可用的正确替代动作。
   - 判停条件：若策略选择正确，继续审计执行，不能因最终失败反推模型有错。

4. **审计动作面**
   - 对照模型发出的调用与实际执行：工具是否可发现、schema 是否表达能力、权限是否足够、参数是否被包装层静默改写、动作是否真实提交。
   - 完成标准：得到“模型意图 → 调用参数 → 适配器变换 → 环境副作用”的逐字段链路。
   - 判停条件：缺工具、缺权限或参数失真时，标记 `action` 为首个断点，跳到步骤 6。

5. **审计反馈面**
   - 检查每个动作的成功、失败、pending、对象 ID 与版本是否写回下一轮；搜索相同参数重复调用和无验证完成声明。
   - 完成标准：每个副作用都有后续决策可消费的真实观察，且能区分未执行、执行中、失败与成功。
   - 判停条件：结果缺失或语义不明确时，标记 `feedback` 为首个断点。

6. **实施最小修复并做固定回归**
   - 只修首个断点：补观察通道、修决策约束、增加动作接口或回写结果；保持其他变量不变重跑样本与保留集。
   - 完成标准：触发失败被修复，正常任务未退化，成本与延迟变化已记录。
   - 判停条件：若四面均有证据完备且策略仍稳定失败，才把升级模型列为候选；一次只验证一个改动。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 尚未构建 Agent，只是在比较架构方案；应先用 `choose-agent-autonomy`。
- 纯信息查询或普通软件故障已有确定堆栈，不涉及模型观察、动作或反馈链路。
- 目标本身没有定义；先澄清业务成功条件，否则四面都无法判定对错。

### 作者在书中警告的失败模式

- **ce003 轨迹缺少工具结果反馈**：动作执行了但结果没回上下文，Agent 会盲目循环。
- **ce040 工具静默改写模型参数**：模型所见动作与环境实际动作不同，策略无法从反馈诊断真实因果。
- **ce055 模型自报完成替代环境验收**：完成措辞属于轨迹，不等于环境状态已经改变。

### 作者的盲点 / 时代局限

- `LLM + 上下文 + 工具` 是强工程抽象，但未穷尽身份、组织治理、经济激励与责任归属；四面均正常不代表业务系统整体合理。
- 书中证据偏头部模型、软件工具与仿真环境；社会互动、隐性知识和不可形式化价值判断未必能被四面表格充分定位。
- Harness 能补偿当前模型不可靠，不证明增加中间层永远优于收窄任务或采用确定性软件。

### 容易混淆的邻近方法论

- 自治选型回答“应该造什么”，本方法回答“已经造出的系统坏在哪里”。
- 首错归因回答“轨迹哪一步首先偏离”，本方法进一步判断该偏离属于观察、策略、动作还是反馈边界。
