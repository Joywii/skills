# 多时间尺度的感知-规划-技能-控制闭环

## R — 原文 (Reading)

> 无论采用哪种实现，都应该把“任务顺序”和“眼前动作”分开

来源：第 9 章 9.3.2 “机器人控制的基本结构”，PDF 第 270 页。

## I — 内化 (Internalization)

长任务失败常不是模型不会规划，而是同一个生成循环同时承担分钟级目标、秒级技能和毫秒级控制。时间尺度与风险不同，接口和验收也必须不同。

目标层定义可验证终态和硬约束；规划层选择子目标顺序并在环境变化时重排；技能层提供有前置条件、后置条件、超时和安全边界的原子动作；低层控制器处理坐标、速率、标定、碰撞、急停等高频确定性约束。

Computer Use 与机器人都需要感知-行动-反馈闭环。模型只能根据当前观察提出候选动作；动作改变环境后，旧截图或旧传感器状态立即过期，必须重新观察再决定。

动作分块在吞吐/平滑性与观察新鲜度之间取舍。块越长，执行越顺，但对环境突变越开环；块长度应按风险与变化速度动态决定，并允许中断。

世界模型和模拟器可以预测后果、比较候选、提前暴露风险，却不是现实真值。最终完成必须由真实新观察、后端状态与独立安全层验收。

## A1 — 作者案例 (Author's Cases)

### 案例 1：编码与文件系统作为开放任务技能核

- **问题**：开放式任务怎样从语言计划落到可复用、可验证动作？
- **方法**：第 5 章以 Manus/OpenClaw 类系统说明编码与文件系统把复杂目标转成脚本、文件和可执行工件。
- **结论**：元能力应封装为有产物与验证的技能，而不是让高层每轮重写低层动作细节。
- **结果边界**：编码元能力适合软件/信息任务，不代表所有物理任务都应转成代码。

### 案例 2：Computer Use 遇 CAPTCHA 后重规划

- **问题**：网页路径不可用时，Agent 是继续执行旧计划还是基于新观察恢复？
- **方法**：实验 9-5/9-6 中 Qwen3-VL 遇 CAPTCHA 后切换到 weather.com，16 步轨迹保留截图与动作并核验结果。
- **结论**：计划必须允许在新观察后换路径，完成由实际页面/轨迹而非口头声明验收。
- **结果边界**：这是 Qwen3-VL 的机制案例，不是对 Claude Computer Use 的复现或通用成功率结论。

### 案例 3：XLeRobot 五阶段闭环

- **问题**：如何把同一物理任务从人类示范逐步推进到安全真机执行？
- **方法**：实验 9-7 至 9-11 依次使用人类遥操作、模拟器、真机 Agent、模拟闭环和 RGB 域随机化。
- **结论**：感知、规划、技能、控制与 sim-to-real 应分阶段验证，仿真只提供证据的一层。
- **结果边界**：模拟闭环结果不能当作真实机器人成功；每一步都需标清环境和硬件。

## A2 — 适用场景 (Application)

### 何时调用

1. 设计浏览器/桌面/手机 Computer Use 的观察、点击、验证与恢复循环。
2. 设计机器人/VLA 的高层规划、原子技能、动作分块、低层安全控制。
3. 长任务计划正确但执行使用旧状态、连续误点、重复动作或口头提前完成。
4. 使用模拟器或世界模型预测动作后果，需要划定真实验收边界。
5. 收到 “hierarchical agent control”, “plan versus skill”, “action chunking”, “closed-loop computer use”, “world model for robotics”等英文请求。

## E — 执行步骤 (Execution)

### 1. 定义目标终态与安全不变量

把“完成任务”改写为可由页面、后端、传感器或测试观察的终态；列出全程不可破坏的权限、碰撞、速度、工作区和副作用边界。

- **完成标准**：终态与每条不变量都有独立观察器，且模型自报不能触发完成。
- **判停点**：没有现实状态验收或急停能力的高风险物理任务不得进入自主执行。

### 2. 划分四层与时间尺度

分别定义目标层、规划层、技能层、低层控制层的输入、输出、频率、权限和责任；高层不得越过技能直接发任意连续控制。

- **完成标准**：每个动作能定位到唯一层，跨层接口结构化；需要 50-1000 Hz 的控制不由 1-10 Hz LLM 直接输出。
- **判停点**：同一循环同时生成长期步骤和任意关节角/连续坐标时，先重构分层。

### 3. 封装有边界的原子技能

为 `click/type/open/pick/place/verify/stop` 等定义前置条件、参数范围、预期后置状态、超时、幂等性、取消与失败码。

- **完成标准**：非法参数在执行前被拒绝，每个技能结束都返回结构化真实状态而非仅“成功”。
- **判停点**：高风险技能只靠自然语言提醒或没有超时/急停时，不允许注册。

### 4. 建立观察-动作-再观察循环

每次有状态动作后等待环境稳定，获取新截图/传感器/后端状态；比较预期与实际，再继续、重试、回滚或重规划。

- **完成标准**：任一连续动作链都能证明上一动作后有新观察，重复观察与重复动作有检测和上限。
- **判停点**：多个动作共用旧截图，或完成声明没有新环境证据时立即中断。

### 5. 调整动作块与中断策略

按环境变化速度、动作风险、推理延迟和控制平滑度选择 chunk；块内监测偏差，支持用户、安全层或新事件提前中断。

- **完成标准**：在扰动回放中，chunk 长度满足成功率与延迟阈值，环境突变能在安全预算内停止。
- **判停点**：成功率随 chunk 增长越过阈值，或突变后仍执行到块末，则缩短或拆分技能。

### 6. 分层验证预测、仿真与现实

世界模型只排序候选；模拟器用于覆盖和安全筛选；最终以真实新观察验收。分别报告离线、仿真、影子、真机/真实 GUI 结果。

- **完成标准**：每个结论标明环境，真机上线前完成域随机化、标定、小流量闭环和人工安全监护。
- **判停点**：预测画面或仿真成功被直接当真实完成，或坐标缩放未校准时拒绝部署。

### 7. 验收恢复与退出

注入页面跳转、弹窗、坐标偏移、物体移动、传感器丢失、技能超时；验证重观察、换路径、回滚、人工接管与停止。

- **完成标准**：每种已知故障都进入有限恢复路径，超过预算安全停止；完整轨迹可回放到每个观察与动作版本。
- **判停点**：状态不变却持续重试、低层安全告警被高层覆盖，或无法人工接管时不得发布。

## B — 边界与禁区 (Boundary)

### 不要在以下情况使用

- 只有纯文本规划、不控制外部环境：无需低层控制分层。
- 固定步骤能由确定性状态机完成：优先普通工作流，不用开放式 Agent。
- 调 PID、运动规划器或驱动固件：这是专业控制算法，不由本 Skill 替代。
- 没有新观察、权限边界或安全停机的真机任务：不得自主化。

### 明确反例与警告

- **ce003 观察断裂**：工具结果没回写会让 ReAct 盲目循环。
- **ce043 OCR 丢空间**：布局敏感 GUI 只保留线性文本，会配错控件和行列。
- **ce055 自报完成**：没有环境验收便声称完成是过早终止。
- **ce097 旧截图开环**、**ce098 坐标缩放**、**ce099 时序盲区** 约束 GUI 感知与定位。
- **ce100 直接关节控制**、**ce101 长动作块**、**ce102 模仿非后果**、**ce103 预测非现实**、**ce104 仿真外推** 约束机器人分层与证据强度。

### 阶段 0 批判边界

- Computer Use、VLA 和世界模型在 2025-2026 年快速演化，具体模型能力、坐标协议和硬件结果不稳定，需用目标设备重测。
- 书中机器人与 GUI 案例是有限演示，模拟器结果不能建立真实世界安全性，跨机器人、材质、光照和长期运行复现不足。
- 作者的软件/文件系统背景可能高估编码作为通用元能力；物理控制仍需领域工程师、确定性控制器和法规安全流程。
- 更强端到端模型可能合并部分规划与技能，但高频硬安全、真实观察和最终验收不应被概率生成吞并。
