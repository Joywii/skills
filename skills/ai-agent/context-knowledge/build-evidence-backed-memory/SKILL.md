# 追加证据-派生视图的记忆与知识生命周期

## R — 原文 (Reading)

> User-as-Code 先把对话事实追加到不可变日志，再周期性重建结构化用户模型；经验学习同样应先保存证据，再离线生成可变知识。
>
> — 李博杰，第 8 章 8.2.1「将经验沉淀为知识」，PDF 第 243 页（书内第 235 页）

---

## I — 方法论骨架 (Interpretation)

长期记忆的核心不是“保存更多”，而是把**不可变证据**和**可变解释**分开。

原始陈述、文档、工具结果和已评价轨迹先以追加记录保存，带来源、时间、主体、范围、验证状态和隐私标签。结构化用户卡片、当前事实视图、摘要、目录与向量索引都是从证据生成的派生物，可以重建、修订和撤销，不能反过来成为唯一来源。

冲突不应自动由“最新一条”获胜。两条记录可能分别适用于不同时间、对象或地区；系统应保留版本，显式建模并存、替代、未决和有效期。经验知识还需要跨多条成功、失败和部分成功轨迹对照，并在留出任务上证明迁移后才能发布。

读取时让小型概览提供全局导航，再按需回到原始证据取细节。这样既避免把全部历史塞入上下文，也防止摘要代际更新造成知识漂移。

## A1 — 书中的应用 (Past Application)

### 案例 1：从对话分块到双层用户记忆（c022）
- **问题**：孤立对话块无法区分多辆车、多次电汇修改和跨会话时间关系；全部历史常驻又不可扩展。
- **方法论的使用**：作者给原始分块补人物、时间和意图前缀，以 Advanced JSON Cards 常驻关键概览，再按需检索原对话证据。
- **结论**：结构化概览负责发现跨会话关联，原始证据负责消歧、验证与细节。
- **结果**：Agent 能区分多辆车、识别电汇指令先后，并把机票与护照到期日关联后主动提示风险。

### 案例 2：从多条 GAIA 轨迹提炼经验文档（c075）
- **问题**：一次成功轨迹可能包含偶然绕路，直接摘要入库会把相关性误当策略。
- **方法论的使用**：作者把成功、失败和部分成功轨迹分组，建立支持与反驳证据，归纳适用条件、例外和来源，再用未参与提炼的任务测试迁移。
- **结论**：反思只是草案；只有与环境结果一致、跨轨迹支持且正向迁移的内容才进入正式知识。
- **结果**：验收要求留出任务表现提高且无负迁移；书中未给统一量化结果，因此不能把生成文档本身视为学会。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 设计用户偏好、实体关系、历史政策或跨会话长期助理记忆。
2. 新事实与旧记录冲突，不确定覆盖、并存、标过期还是等待审核。
3. 知识库多轮摘要后细节漂移，结论无法追溯到原始来源。
4. 想从生产轨迹或反馈提炼可复用经验，但只有单次成功或未验证反思。

### 语言信号 (用户的话里出现这些就应激活)

- “用户记忆要怎么做版本和来源？” / “provenance-aware user memory”
- “新记录应该覆盖旧记忆吗？” / “overwrite or version conflicting memory?”
- “索引和摘要哪个才是 source of truth？”
- “怎么从多条轨迹提炼经验而不是记住一次成功？” / “evidence-backed experience memory”

### 与相邻 Skill 的区分

- 与 `distill-explicit-agent-state` 的区别：本 skill 保存跨会话、可版本化的长期事实与经验；后者维护单次运行的当前状态投影。
- 与 `choose-rag-retrieval-mode` 的区别：本 skill 设计知识如何写入、更新和审计；后者决定查询时用固定检索、迭代探索还是全库统计。
- 与 `govern-continuous-agent-evolution` 的区别：本 skill 只治理知识载体；后者还治理 Prompt、程序、参数更新的发布与可信根。
- 与 `route-agent-updates` 的区别：本 skill 在知识载体已选中后设计写入生命周期；后者先在知识、指令、程序与参数之间选择载体。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **定义记忆对象与保留边界**
   - 区分用户事实、世界知识、行动经验和当前任务状态；为每类定义用途、保留期、隐私、删除权和发布门槛。
   - 完成标准：每条候选都能回答“为哪个未来决策服务”，不保存无差别聊天历史。
   - 判停条件：没有合法用途、用户授权或删除机制的敏感信息不得进入长期存储。

2. **设计追加证据记录**
   - 至少记录 `record_id`、原始内容/引用、来源主体、采集时间、适用对象与范围、验证状态、置信度、隐私标签和环境版本。
   - 完成标准：任何正式结论都能追溯到一条或多条不可变证据，删除请求可定位影响范围。

3. **分离提取、核验与发布**
   - 提取器只生成候选；用用户确认、环境真值、独立来源或跨轨迹对照核验；达到门槛后才进入正式视图。
   - 完成标准：推断、用户明确陈述、外部文本和已验证结果具有不同状态，不会同权保存。
   - 判停条件：证据冲突或不足时标记 `unresolved`，不得让模型猜成唯一事实。

4. **建模冲突和时间**
   - 判断新旧关系是替代、并存、范围不同还是未知；保留历史版本，记录有效期、作用域和替代边。
   - 完成标准：系统既能回答“当前是什么”，也能回答“过去何时有效、依据是什么”。

5. **生成可重建派生视图**
   - 从证据构建关键事实卡片、实体关系、时间视图、目录、摘要和检索索引；概览常驻，细节按需回查原文。
   - 完成标准：删除所有派生物后可从证据重建；索引损坏不等于知识丢失。

6. **做迁移、冲突与隐私验收**
   - 测试直接召回、跨实体/跨时间组合、冲突消歧、主动关联、历史问题、删除和越权访问；经验文档用留出任务测正/负迁移。
   - 完成标准：关键层级达到目标，所有答案带正确范围和来源，安全/隐私用例一票否决。
   - 判停条件：视图只能追溯到旧摘要、单条轨迹无法确定共性，或出现负迁移时不发布并回到证据层。

7. **周期性整理而非破坏性覆盖**
   - 合并重复、标记过期、重建索引和当前视图，同时保留审计版本与回滚路径。
   - 完成标准：知识库增长与有效能力相称，旧规则不会因“最新”而无范围地消失。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- TODO、工具次数、锁和 pending job 等当前任务状态；使用显式状态栏。
- 仅需一次回答、没有未来复用价值的信息，不应为“可能有用”永久保存。
- 纯检索性能问题且写入生命周期已可靠；使用检索模式选择与评估。

### 作者在书中警告的失败模式

- **ce026 把未核验提取写成长期事实**：一次误听会被持久化并跨会话放大。
- **ce027 用单一记忆格式覆盖所有信息**：原子事实、关系、叙事和时间信息具有不同表示需求。
- **ce028 冲突时覆盖历史版本**：破坏性更新消除有效期和历史证据。
- **ce034 用摘要更新摘要造成知识漂移**：派生物成为来源后，每代有损变换无法校正。
- **ce035 把最新记录强行解释为唯一真相**：时间顺序不等于语义替代，范围不同的事实可能并存。

### 作者的盲点 / 时代局限

- 本书对隐私、合规、数据主体权利和组织数据治理的展开弱于技术架构；真实用户记忆必须增加同意、删除、地域和审计要求。
- 许多实验依赖 LLM 提取与自动评判，可能共享同源偏差；可追溯不自动保证事实真实。
- 双层记忆和复杂索引需要运维资源，小团队应先证明跨会话价值，不把“长期记忆”当默认功能。

### 容易混淆的邻近方法论

- 保存原始轨迹不是持续学习；未评价、未对照、未迁移验证的日志只是证据池。
- 当前结构化卡片是派生视图，不是可以删除来源后永久保留的唯一真相。
